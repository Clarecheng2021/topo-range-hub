# 工控拓扑自动生成靶场：产品与技术基线

## 1. 产品目标

输入企业已有的 PNG、JPEG、扫描 PDF 或绘图软件导出的网络拓扑，自动恢复区域、设备、文字属性、链路和协议，经人工复核后生成可部署、可操作、可验证的隔离靶场。

本项目中的“真实”分为三个层级，界面必须明确标识，不能混称：

1. **网络真实**：独立网络命名空间、接口、二层链路、路由和访问控制真实存在。
2. **服务真实**：HMI、SCADA、Historian、PLC/RTU 模拟器及 Modbus TCP、OPC UA 等服务能够交互。
3. **设备真实**：使用获得授权的厂商虚拟镜像、Windows 虚机，或通过受控资源适配器连接实验室物理设备。

系统不得根据图片臆造不可见的固件版本、账号密码、PLC 程序、工艺参数或端口配置；缺失信息进入“待确认”状态。

## 2. 端到端工作流

1. 上传图片或 PDF，保存原件、缩略图、哈希和来源元数据。
2. 图像预处理：旋转校正、放大、去噪、对比度增强、分块和页面拆分。
3. OCR 提取设备名称、IP、网段、协议、端口、区域标题和注释。
4. 目标检测识别防火墙、交换机、路由器、服务器、HMI、PLC、RTU、摄像机、传感器等图标及边界框。
5. 计算机视觉追踪实线、虚线、箭头、总线、环网和跨页连接符，生成链路候选。
6. 多模态模型识别全局语义、Purdue 层级、IT/OT/DMZ 区域，并校验 OCR、图标和链路候选之间的冲突。
7. 图重建服务生成统一 Graph JSON，执行孤立节点、重复节点、跨区链路、接口容量和协议合理性检查。
8. 可视化编辑器显示原图叠加、边界框、识别依据和置信度，允许增删、拖拽、改类型、改属性和重连。
9. 场景编译器把抽象设备映射为运行模板，并生成 Containerlab、Docker/Compose、虚机或物理资源计划。
10. 用户确认部署计划后，在隔离执行节点创建环境；执行健康检查、连通性测试和服务探测，再回传可访问入口。

## 3. 为什么采用混合识别

单一 OCR 模型擅长文字但不能稳定恢复复杂连线；单一多模态模型擅长全局理解，但可能补全图片中不存在的设备或关系。因此必须保留可追溯的多源证据：

| 子任务 | 默认能力 | 输出 |
| --- | --- | --- |
| 文本与布局 | DeepSeek-OCR-2 或可替换 OCR 适配器 | 文本、坐标、置信度 |
| 设备图标 | 可训练目标检测器 | 类型、边界框、置信度 |
| 连线与区域 | OpenCV 线段/骨架/轮廓算法 | 端点、折点、线型、区域框 |
| 全局语义 | 可替换 VLM 适配器 | 区域、层级、关系候选 |
| 图谱融合 | 规则 + 图算法 | nodes、links、zones、冲突项 |

每个节点和链路都应保存 `evidence` 与 `confidence`，低置信度或来源冲突必须进入人工复核队列。

## 4. 核心模块

```text
Web Editor
  -> API Gateway / Job API
     -> Image Service
        - preprocess
        - OCR adapter
        - device detector
        - line/zone detector
        - multimodal verifier
     -> Graph Service
        - entity resolution
        - edge reconstruction
        - validation
        - versioning
     -> Range Engine
        - template catalog
        - resource planner
        - containerlab compiler
        - VM / physical adapters
        - deploy / inspect / destroy
     -> Validation Service
        - node health
        - link reachability
        - protocol probes
        - result report
```

长时间识别和部署任务采用异步作业模型，API 返回 `job_id`；前端通过轮询或事件流获得阶段、进度、日志、警告和可重试错误。原图、模型中间结果和部署产物使用对象存储，拓扑版本及审计记录使用关系数据库。

## 5. 设备到运行资源的默认映射

| 抽象设备 | MVP 运行方式 | 后续真实化方式 |
| --- | --- | --- |
| 二层交换机 | Linux bridge / Open vSwitch | 厂商虚拟交换机 |
| 路由器 | Linux namespace + FRR | 厂商虚拟路由器 |
| 防火墙 | Linux + nftables | 获得授权的虚拟防火墙 |
| Linux/业务服务器 | Docker 容器 | 指定业务镜像或虚机 |
| Windows/工程师站 | 占位节点 | Windows VM 模板 |
| PLC | OpenPLC 或协议模拟器 | 厂商软 PLC / 实验室物理 PLC |
| RTU/现场设备 | Modbus/OPC UA 自定义模拟器 | 物理 RTU/仪表适配器 |
| HMI/SCADA | Web HMI/SCADA 模拟器 | 授权软件镜像或虚机 |

映射结果不是静默替换。编译报告必须列出“原设备类型、选用模板、仿真层级、未实现能力和所需授权”。

## 6. 隔离与安全约束

- 默认 `internet_egress=false`、`production_bridge=false`。
- 生成的管理网与业务网使用项目独立地址池，部署前检查与宿主机、VPN 和已有实验网是否冲突。
- 物理设备只通过登记过的 `resource_id` 引用，不能由识图结果直接绑定。
- 部署前先生成计划并支持 dry-run；创建、销毁和桥接操作写入审计日志。
- 外部镜像使用允许列表、固定 digest、漏洞扫描和许可证记录。
- 靶场服务不得包含真实生产凭据、配置备份或未脱敏流量。

## 7. 数据集与评测

训练与回归集按拓扑复杂度和图片质量分层：

- L0 设备单元，L1 单产线，L2 SCADA 层，L3 IT/OT/DMZ，L4 Purdue 全厂，L5 大型多厂区。
- C0 高分辨率原图，C1 PDF，C2 低分辨率，C3 JPEG 压缩，C4 截图，C5 小字密集，C6 裁剪，C7 工程软件画布。
- 行业至少覆盖水务、电力、制造、石化、轨交和楼宇控制。

每张样本保存原图、节点、链路、区域、层级、协议、边界框及许可元数据。核心指标分别计算，禁止只报告一个“总体识别率”：

- 设备检测 Precision / Recall / mAP。
- OCR 字段准确率与 IP/网段格式准确率。
- 链路 Precision / Recall / F1。
- 区域与层级 IoU/准确率。
- 图编辑距离及人工修正次数。
- 场景编译成功率、节点启动率、链路连通率和协议探测通过率。

## 8. 版本路线与验收门槛

### V0.2（当前 Demo）

- 钟山水厂固定模板可生成 41 个设备和 40 条链路。
- 支持拖拽、增删、重连、属性校正以及 JSON/Containerlab 导出。
- 限制：不是通用图片识别，运行模板仍以网络占位节点为主。

### V0.3（下一里程碑：通用解析）

- 对未内置模板的 PNG/JPG/PDF 执行真实 OCR、图标检测和连线追踪。
- 输出符合 `topology-schema/topology.schema.json` 的版本化 Graph JSON。
- 节点、链路均显示识别证据和置信度；低置信度可筛选复核。
- 同一输入可重复运行并比较模型输出，不能靠文件名、尺寸或宽高比匹配模板。

### V0.4（可运行网络）

- 场景编译器生成合法 Containerlab 文件并先执行 dry-run。
- 支持 Linux 主机、二层交换机、FRR 路由、防火墙、HMI、PLC 和传感器模拟器。
- 部署后自动验证节点状态、二层/三层连通性，失败项定位到具体节点或链路。

### V0.5（可交互工控场景）

- 优先贯通 Modbus TCP，再逐步增加 OPC UA、S7、EtherNet/IP、DNP3、IEC 104/61850。
- PLC/RTU 数据、HMI 画面和 SCADA 标签具有一致的数据模型和可观察状态。
- 支持基线拓扑与新上传拓扑的差异检测。

### V1.0（企业化交付）

- 多租户项目、权限、审计、模板和镜像治理。
- Containerlab/Docker、虚机、GNS3/EVE-NG 及受控物理设备的混合编排。
- 识别、人工修正、编译、审批、部署、验证和销毁的全生命周期可追溯。

## 9. 下一步实施顺序

先完成 V0.3 的后端作业 API、统一 Schema、OCR 适配器、图标/连线检测和原图叠加复核；随后才把当前前端的“模板匹配”替换为真实识别任务。这样可以先解决最容易被掩盖、也最影响靶场正确性的链路重建问题，再进入真实资源编排。
